# CV 论文宏观评价原型系统（CV-Paper-Eval MVP）设计文档

> 项目：基于知识图谱与大模型 Agent 的计算机视觉论文宏观学术评价研究
> 子项目：CV 论文评价原型系统（MVP）
> 日期：2026-08-27
> 状态：待用户评审
> 前置成果：阶段一文献调研（71 篇文献、98 条原始候选指标、30 个语义簇）

## 1. 背景与目标

阶段一已完成 CV 论文宏观学术评价的文献调研与候选指标体系构建（30 个语义簇，其中论文层、纯文本可提取、CANDIDATE 状态的维度约 14 个）。本子项目在阶段一成果之上，构建一个**可运行的原型系统**：

输入一篇 CV 论文（PDF / arXiv 链接 / 粘贴文本），系统自动输出一份**结构化评价报告**，报告以论文内部实验指标为证据主干，给出创新性、科学性、有效性等宏观维度的得分、证据与综合结论。

本项目遵循研究边界：

- 研究对象是论文层面的宏观学术评价；
- Accuracy、Precision、Recall、F1、mAP、IoU、FPS、PSNR 等属于论文内部实验/模型性能指标，**不作为核心评价指标**；
- 实验指标作为支撑“方法有效性”“实验充分性”“技术稳健性”等宏观维度的**证据**；
- 影响因子、JCR 分区等期刊层信息、H 指数等作者层信息、引文/Altmetrics 等影响力信息**不属于论文自身属性**，MVP 不联网评分，报告中标注“未评估”；
- 所有核心评价指标必须有文献依据（接阶段一 evidence）或专家审核依据；
- 对存在争议的指标（merge_status=REVIEW 的簇）不进评分，标注“待审核”。

## 2. 范围与边界

### 2.1 本版本（MVP v1）范围

- 仅针对 **CV 领域**论文（不同学科评价标准不同，后续再扩展）；
- 单篇论文独立评价，对比对象为论文内部报告的基线与 SOTA 声明，不依赖外部数据；
- 三种输入：PDF 文件、arXiv 链接、粘贴文本；
- 输出：Markdown 报告 + JSON 结构化结果；
- 双通道抽取：通道二（实验指标抽取与对比）为证据主干，通道一（宏观定性证据）辅助覆盖指标无法支撑的维度；
- 模型后端：默认 DeepSeek API，provider 可配置切换；
- 技术形态：确定性流水线（模块化、可单测、可复现），Agent 编排留待后续版本。

### 2.2 非目标（Non-goals）

- 不做引文/期刊/作者层评分（外部数据，标注“未评估”）；
- 不做其他学科的评价（知识库预留“学科适用性”字段）；
- 不做网页/交互界面（v2 再考虑）；
- 不做批量评价流水线（v1 聚焦单篇）；
- 不引入 RAG 与 Agent 编排（后续版本）；
- 不做综合权重算法研究（v1 用可配置权重，默认等权，标注可替换）。

## 3. 总体架构与数据流

```
输入（PDF / arXiv 链接 / 粘贴文本）
  → L1 解析层      PDF→结构化文本（标题/摘要/章节/段落）；arXiv 链接→元数据+PDF；表格抽取与文本化
  → L2 指标抽取层  通道二（主线）：任务/数据集/指标名/数值/对比基线/SOTA 声明/消融设置/统计披露
                   通道一（辅助）：创新点描述、局限性、开放性声明等定性证据句
  → L3 对比分析层   相对基线提升、覆盖数据集数、多基准一致性、统计披露度、SOTA 声明核验
  → L4 维度评价层   对比结果映射到宏观维度；LLM 按 rubric 打分（0-5）+ 置信度 + 证据引用
  → L5 结论报告层   加权总分（权重可配置）、优势/不足、综合结论、未评估/待审核标记
  → 输出：Markdown 报告 + JSON
```

设计原则：

- 证据先于结论：每条维度得分必须可回溯到原文证据（指标行或证据句）；
- 中间层可核验：L2 产出的指标结构化数据、L3 产出的对比结论均独立落盘，可人工检查；
- 模块单一职责：每层独立组件，通过明确的数据结构接口通信，可单独测试。

## 4. 组件设计

### 4.1 输入层

- PDF：本地文件路径，交给解析层；
- arXiv 链接：调用 arXiv API 获取元数据（标题/摘要/作者/年份/venue），下载 PDF 后进入解析层；
- 粘贴文本：直接进入结构化切分（无 PDF 时跳过表格抽取，报告中注明“输入为纯文本，表格证据缺失”）。

### 4.2 解析层

- PDF 解析：pymupdf 提取文本；公式转为占位符（`[EQ]`），图表按图注/表头占位（`[FIGURE n]`、`[TABLE n]`）；
- 表格抽取与文本化：识别表格区域，输出“表头 + 行记录”的扁平结构，供指标抽取使用（指标大多在表格中，本层质量直接影响 L2）；
- 章节切分：标题/摘要/引言/方法/实验/结论/附录 等章节结构化输出；
- 质量抽检：解析模块内置样例级校验（段落数、章节覆盖、表格数），低质量解析在报告中警告。

### 4.3 实验指标抽取层（通道二，主线）

目标：从正文与表格中**尽可能完整**地抽取论文内部评价指标，覆盖 CV 各任务族（见第 5 节清单）。

每条指标记录：

- task（任务类型，如 detection / segmentation / generation）；
- dataset（数据集名与切分，如 COCO val2017）；
- metric_name 与 metric_variant（如 mAP / mAP@0.5:0.95）；
- value 与 direction（越高越好 / 越低越好，如 FID 越低越好）；
- method_key（ours / baseline / 对比方法名 / SOTA）；
- source_location（表格编号或段落定位，可回溯）；
- 归一化说明（同指标不同 variant 不混比，如 mAP@0.5 与 mAP@0.5:0.95）。

抽取方式：LLM（DeepSeek）按指标 schema 做结构化抽取 + 后置校验（抽取的数值必须能在原文定位；数值范围与任务合理性校验，如准确率∈[0,1]）。

### 4.4 指标对比分析层

对抽取结果做结构化对比，产出对比结论集：

- 相对基线/先前方法：提升/下降幅度（绝对与相对）、在几个基准上一致；
- 覆盖率：涉及多少个数据集/任务/设置；
- 一致性：多基准结果方向是否一致；
- 统计披露：是否报告方差/标准差、显著性检验、多次重复（seed）实验；
- SOTA 声明核验：论文声称的 SOTA 与表格数值是否自洽；
- 表格-正文一致性：正文叙述数字与表格数字是否一致。

### 4.5 指标知识库 v1 与宏观维度（通道一辅助）

知识库 v1 为可机读资源（JSON/YAML），记录：

- 每个宏观维度的定义、评价问题、rubric（0-5 分判据）、来源文献（接阶段一 evidence）；
- 指标→维度的映射规则（见下方 v1 草案表）；
- CV 指标 schema（名称、variant、方向、取值范围、归一化规则）；
- 学科适用性字段（本版固定为 CV，字段为后续学科扩展预留）。

指标对比结论 → 维度映射（v1 草案）：

| 论文内部指标对比结果（证据） | 推导的宏观维度 |
| --- | --- |
| 相对基线/先前方法的提升幅度、多基准一致 | 技术稳健性（CL-004）、学术贡献度（CL-003） |
| 数据集/任务覆盖面、跨场景表现 | 实验充分性、泛化性与部署稳健性（CL-007） |
| 消融实验完整性、组件贡献分析 | 实验有效性与偏置控制（CL-006）、贡献归因（CL-003） |
| 方差/显著性检验/多次重复报告 | 统计严谨性与披露（CL-008） |
| 表格-正文一致、SOTA 声明自洽 | 声明-证据一致性（CL-005） |
| 代码/超参/数据版本公开 | 可复现性（CL-009）、开放性与资源可得性（CL-010） |
| 动机、与已有方法的差异（定性证据） | 创新性（CL-001） |
| 相关工作与引用充分性（定性证据） | 相关工作与引用充分性（CL-013） |
| 伦理合规声明（定性证据） | 伦理合规（CL-014） |
| 局限性披露（定性证据） | 局限性与诚实评估（CL-015） |

### 4.6 维度评价层

- 14 个核心评分维度（全部为论文层、文本可提取、CANDIDATE 状态簇）：
  1. 创新性/新颖性（CL-001）
  2. 学术贡献度（CL-003）
  3. 技术稳健性（CL-004）
  4. 声明-证据一致性（CL-005）
  5. 实验有效性与偏置控制（CL-006）
  6. 泛化性与部署稳健性（CL-007）
  7. 统计严谨性与披露（CL-008）
  8. 可复现性（CL-009）
  9. 开放性与资源可得性（CL-010）
  10. 数据集贡献（CL-011）
  11. 表述清晰度（CL-012）
  12. 相关工作与引用充分性（CL-013）
  13. 伦理合规（CL-014）
  14. 局限性与诚实评估（CL-015）
- 每个维度：分数（0-5）、置信度、证据引用（指标对比结论 + 原文证据句）、未评估/待审核标记；
- 不进入评分但在报告中列出的类别：影响力簇（CL-016~021）、期刊层（CL-022）、作者层（CL-023）、评审流程簇（CL-025~029）、元原则（CL-028）、争议簇（CL-002/024/030 及全部 REVIEW 项）。

### 4.7 结论与报告层

- 加权总分：各维度得分按可配置权重汇总，默认等权，报告中注明“权重方案为 v1 默认，后续可替换为熵权法/AHP”；
- 报告内容：论文元信息、各维度得分与证据、实验指标对比摘要表、优势/不足、综合结论、置信度说明、未评估与待审核清单；
- 输出：Markdown（人读）+ JSON（机读），JSON 与抽取/对比中间产物同构，保证可追溯。

## 5. CV 论文内部指标覆盖清单（v1 抽取目标）

原则：覆盖尽可能多的 CV 任务族与常用指标；每条记录方向（越高/越低越好）与归一化注意点。

| 任务族 | 常见指标（方向） | 归一化/注意点 |
| --- | --- | --- |
| 图像分类 | Accuracy、Top-1/Top-5、Balanced Accuracy、Precision、Recall、F1、Macro/Micro F1、AUC-ROC、PR-AUC/AP、Cohen's Kappa（均越高越好） | 数据集/切分不同不可直接比较；类别不平衡时看 Macro F1/AUC |
| 目标检测 | mAP@0.5、mAP@0.5:0.95、AP/AR per class、FPS、Latency（mAP/AP/AR 越高越好；FPS/延迟越高/越低按实际） | mAP variant 必须记录；FPS 与硬件相关，需记录硬件环境 |
| 实例/全景分割 | AP、mAP（实例分割）；PQ、SQ、RQ（全景）；mIoU、Dice、Boundary F1（越高越好） | 与检测指标分开记录 |
| 语义分割 | mIoU、IoU、Pixel Accuracy、Dice、Boundary F1（越高越好） | 类别数/数据集不同不可混比 |
| 目标跟踪 | MOTA、MOTP、IDF1、HOTA、MT/ML、ID Switches、Track mAP（越高越好，ID Switches 越低越好） | 跟踪设置（在线/离线、检测器来源）影响结果 |
| 姿态估计 | PCK/PCKh、OKS-based AP（越高越好） | 关键点定义与归一化方式需记录 |
| 生成模型（GAN/扩散） | FID、KID、sFID、FVD（越低越好）；IS、CLIP Score、生成分布 Precision/Recall、LPIPS、用户偏好（越高越好） | FID 计算实现版本不同差异大；文本到图像需固定提示集 |
| 图像超分/质量 | PSNR、SSIM、LPIPS（PSNR/SSIM 越高越好，LPIPS 越低越好）；NIQE、PIQE、BRISQUE、MUSIQ（越低越好） | 缩放因子/数据集（Set5/Set14/Urban100）不同不可比；PSNR 无参考意义有限 |
| 视频生成/预测 | FVD、IS、KVD（越低/越高按实际） | 帧率/分辨率/长度设置需记录 |
| 深度估计 | AbsRel、RMSE（越低越好）；δ1/δ2/δ3、精度阈值（越高越好） | 深度范围与 mask 方式影响大 |
| 光流估计 | EPE（越低越好）、F1-all（越高越好） | 数据集（KITTI/Sintel）分开记录 |
| 图像检索/度量学习 | mAP、Recall@K、Precision@K、NDCG、MRR（均越高越好） | K 值与 query 集需记录 |
| 行人重识别 | mAP、Rank-1/Rank-5（越高越好） | 训练/测试协议（交叉验证等）需记录 |
| 人脸识别 | 验证准确率、TAR@FAR（越高越好） | 测试集协议（LFW/CFP/ AgeDB）需记录 |
| OCR/文本识别 | 字符/词级准确率、CER（越低越好）、检测 mAP（越高越好） | 语言与数据集分开记录 |
| 动作识别 | Top-1/Top-5、gF1、每类准确率（越高越好） | 数据集切分（训练/测试划分）需记录 |
| 少样本/元学习 | 每 episode 平均准确率、多 seed 均值±方差（越高越好） | 必须记录 episode 设置与 seed 数 |
| 鲁棒性/校准 | 对抗鲁棒准确率、mCE（越低越好）、ECE 校准误差（越低越好） | 攻击设置/扰动类型需记录 |
| 效率/资源 | FPS、Latency、参数量、FLOPs、能耗（按实际方向） | 硬件/框架/精度（FP32/FP16）必须记录 |
| 统计披露 | 多次重复均值±方差、显著性检验（p 值/置信区间）、seed 数 | 作为统计严谨性维度证据 |

通用注意点：

- 同一指标的不同 variant（mAP@0.5 vs mAP@0.5:0.95、Top-1 vs Top-5）绝不混比；
- 每条指标必须带数据集与切分信息，否则标记“缺上下文”，不进对比；
- 方向（higher/lower-is-better）按指标规范固定，LLM 抽取时校验。

## 6. 数据结构（草案）

JSON 顶层结构：

```json
{
  "paper": { "title": "", "authors": [], "year": 0, "venue": "", "arxiv_id": "", "source": "pdf|arxiv|text" },
  "sections": [ { "id": "", "heading": "", "text": "" } ],
  "tables": [ { "id": "TABLE 1", "rows": [ { "header": "", "cells": [] } ] } ],
  "metrics": [ { "metric_id": "", "task": "", "dataset": "", "metric_name": "", "metric_variant": "", "value": 0.0, "direction": "higher|lower", "method_key": "", "source_location": "", "normalization_note": "" } ],
  "comparisons": [ { "comparison_id": "", "metric_ids": [], "type": "vs_baseline|vs_sota|coverage|consistency|statistics", "conclusion": "", "evidence_locations": [] } ],
  "dimension_scores": [ { "cluster_id": "CL-001", "dimension": "创新性/新颖性", "score": 4, "confidence": "high|medium|low", "evidence": [], "status": "evaluated|not_applicable|review|not_evaluated" } ],
  "summary": { "weighted_score": 0.0, "weights": {}, "strengths": [], "weaknesses": [], "conclusion": "", "caveats": [] }
}
```

约束：

- 每个 metric/comparison/dimension_score 都有唯一 id，report 中的证据必须引用这些 id 或原文定位；
- status=not_evaluated 的维度（影响力/期刊/作者）必须出现在报告中并说明原因；
- status=review 的维度（争议簇）只展示证据与待审核说明，不计分。

## 7. 数据集构建

| 数据 | 规模 | 用途 |
| --- | --- | --- |
| 语料库 | 300～500 篇（近 3～5 年 CVPR/ICCV/ECCV/TPAMI 主方向） | 系统开发与知识库迭代 |
| 演示集 | 20～30 篇 | Demo 与示例报告 |
| 精标集 | 30～50 篇（作者本人标注，含双人一致性子集） | 抽取质量与评分一致性验证 |

- 来源：arXiv（首选）、CVF Open Access（CVPR/ICCV/ECCV 官方开放 PDF）、Semantic Scholar/arXiv API（元数据）、OpenReview API（可选，仅取审稿意见作专家评分参照，不入正文语料）；
- 记录：paper_id、标题、作者、年份、venue、DOI、arXiv id、摘要、全文解析文本（按章节）、来源与获取时间；
- 版权：仅使用合法开放来源，库内不存储、不重新分发 PDF 原文；
- 标注 schema：14 个维度 ×（是否有证据、证据句位置、证据类别、专家评分 0-5）；先标 5 篇校准 schema，再批量标注；
- 划分：开发集（模型调试）与测试集（最终评估）分开，防止过拟合演示。

## 8. 验证实验设计

1. 指标抽取质量：模型抽取 vs 人工标注（精标集），指标级 P/R/F1、数值准确率、任务/数据集字段一致率；
2. 对比分析质量：对比结论与人工判断一致率；
3. 评分质量：模型维度得分 vs 专家评分，Spearman 相关与 ICC；
4. 消融实验：有知识库约束 vs 无约束（去掉 rubric/映射）的评分差异；
5. 稳定性：同一篇低温度多次运行，分数波动与结论变化；
6. 可追溯性：抽样核验每条得分证据能回指原文。

## 9. 里程碑与交付物

| 里程碑 | 任务 | 产出 |
| --- | --- | --- |
| M0 设计定稿 | 本 spec 评审通过 → 实施计划（writing-plans） | 设计文档、实施计划 |
| M1 数据收集 | arXiv/CVF 元数据+PDF 抓取、解析入库 | 300～500 篇语料库 + 工具脚本 |

| M3 解析管线 | PDF→结构化文本、表格抽取、章节切分、单测 | 解析模块 |
| M4 抽取+对比+评分引擎 | 指标抽取、对比分析、维度评价、证据校验 | 核心引擎 + 单测 |
| M5 报告生成 | Markdown/JSON 报告、示例报告 | 20～30 篇演示报告 |
| M6 标注与评估 | 精标 30～50 篇、相关性/消融/稳定性实验 | 质量评估报告 |

## 10. 风险与对策

| 风险 | 对策 |
| --- | --- |
| PDF/表格解析质量不足，指标抽取缺数据 | 表格抽取专门处理；解析质量抽检与报告警告；精标集暴露失败模式 |
| LLM 幻觉（编造数值/证据） | 强制原文定位 + 数值合理性校验 + 后置存在性校验 + 置信度字段 |
| 评分主观性 | rubric 细化 + 与专家评分一致性验证；争议簇不进总分 |
| 指标 variant 混淆导致对比失真 | 指标 schema 强制 variant/方向/数据集字段；归一化规则 |
| 成本 | 分簇批处理、结果缓存、可配置模型/温度 |
| 版权 | 仅用 OA/arXiv；库内不存 PDF 原文 |

## 11. 待确认假设

1. 模型后端默认 DeepSeek API（provider 可切换）——需确认可用的 DeepSeek API Key；
2. v1 输入支持 PDF + arXiv 链接 + 粘贴文本（arXiv 需联网）；
3. 报告输出 Markdown + JSON；
4. 语料 300～500 篇、精标 30～50 篇；
5. 权重默认等权，可配置。

以上假设在实施计划中作为配置项落实；如与实际情况不符，在实施前调整。
